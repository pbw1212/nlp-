# 手动验收流程表（前端 P0–P5）

> 目的：用最少的 API 花费，逐屏确认"能用、数据真、失败不装"。
> 总花费上限：**约 0.05 元**（合计约 20–25 次模型调用）。
> 总耗时：**约 20 分钟**。
>
> **关键前提**：`multi_fixed` 模式下连普通闲聊都会走四角色协作，而协作链路现在有已知后端缺陷
> （见 `docs/bug-report-verifier-receipts.md`）会失败。所以：
> **对话/记忆/任务/上下文 → 用 `single` 测；协作失败态 → 用 `multi_fixed` 测。**

## 7. 出问题怎么定位（先分清前端还是后端）

| 现象 | 先查这个 | 判断 |
|---|---|---|
页面白屏/编译错 | 终端 2 输出、F12 Console | 前端 |
「后端未连接」 | 终端 1 是否在跑；token 是否最新（重启会变） | 配置 |
某屏一直转圈 | 浏览器 Network 里对应 `/api/...` 的响应码与 body | 404/400 = 接口问题；200 但空 = 后端数据问题 |
操作报错但不知道谁的错 | 用 curl 直接打接口（见下） | curl 也报错 → 后端/数据；curl 正常 → 前端 |

直接验证某个接口（绕开界面）：

```powershell
$b='http://127.0.0.1:8787'
# 无 token 模式（--no-token 启动时）：
Invoke-RestMethod "$b/api/meta" | ConvertTo-Json -Depth 3
Invoke-RestMethod "$b/api/memories" | ConvertTo-Json -Depth 3
Invoke-RestMethod "$b/api/tasks/status" | ConvertTo-Json -Depth 3
Invoke-RestMethod "$b/api/traces?limit=3" | ConvertTo-Json -Depth 3
# 带 token 模式：
$t='<粘贴 token>'
Invoke-RestMethod "$b/api/meta" -Headers @{ 'X-MAPAS-Token'=$t } | ConvertTo-Json -Depth 3
```
